# Requirements and Design Specification

## 1. Product Requirements

**Objective**: Build an Autonomous Machine Learning Research Tool that can dynamically screen, analyze, and validate stock market strategies based on natural language queries. 

**Core Use Case**: 
- A user asks a natural language question, e.g., *"Find me all stocks that have been stable and oscillate 10% up and down periodically."*
- The tool autonomously gathers data, runs the necessary math to identify candidates, backtests them to verify profitability, and outputs a ranked list of the top 10 most reliable stocks.

**Constraints & Preferences**:
1. **Frontend Integration**: Re-purpose the existing `stock-threshold-analyzer` repository and continue using the GitHub Pages setup (`sma/`) as the frontend for exploration and presentation.
2. **Vendor Agnosticism**: The LLM core must be vendor-agnostic (easily swappable between OpenAI, Anthropic, Gemini, etc.).
3. **Primary Model**: Start implementation using Anthropic (Claude).
4. **Data Horizon**: Must support screening over multi-year periods (e.g., 5-10 years) to validate long-term reliability.

---

## 2. System Design Specification

The architecture is divided into five core layers, functioning together as a multi-step Agentic ReAct (Reasoning + Acting) pipeline.

### Layer 1: Data Ingestion
- **Tooling**: `yfinance`
- **Purpose**: Pulls 5–10 years of split- and dividend-adjusted daily OHLCV (Open, High, Low, Close, Volume) data for a large universe of stocks (e.g., S&P 500 constituents).
- **Execution**: Run on-demand by the agent when evaluating candidate tickers.

### Layer 2: Strategy & Quant Logic Engine
- **Tooling**: `pandas-ta`
- **Purpose**: Computes technical indicators required to fulfill the user's prompt (e.g., Simple Moving Average (SMA), Bollinger Bands, Z-scores, RSI).
- **Execution**: The agent translates the user's natural language into mathematical parameters (e.g., `±10% threshold`, `200-day SMA`) and executes the screening logic across the ingested data.

### Layer 3: Backtesting Engine
- **Tooling**: `Backtesting.py`
- **Purpose**: Validates the filtered stocks to prove the identified pattern (e.g., oscillation) was actually tradeable and profitable, eliminating false positives.
- **Execution**: Takes the signals generated by Layer 2 and simulates historical P&L.

### Layer 4: The Agent Core (LLM + Orchestration)
- **Tooling**: `langchain` + `langchain-anthropic`
- **Purpose**: The "Brain" of the system.
- **Workflow**:
  1. Receives the user's query.
  2. Uses a **Screener Tool** (wrapping Layer 2) to identify candidate stocks.
  3. Uses a **Backtest Tool** (wrapping Layer 3) to validate the candidates.
  4. Synthesizes the results, formulates the reasoning, and outputs a structured final report.

### Layer 5: Storage & Presentation
- **Storage Format**: The agent outputs a structured JSON file (e.g., `sma/data/research_report.json`).
- **Frontend**: The existing static GitHub Pages site (MkDocs + Plotly).
- **Workflow**: The frontend will be updated to fetch and render the `research_report.json`, dynamically displaying the Top 10 stocks, the agent's textual analysis, and interactive historical charts.
